Hetzner Cloud is the only provider we have run this on. The scripts call Hetzner's own `hcloud` command-line tool, so other clouds would need different scripts.

Where Hetzner's console changes over time, this page links to Hetzner's own instructions instead of describing buttons.

Sections 1 to 8 are one-time setup. Section 9 is the 3 steps.

## 1. Make an account

Sign up at Hetzner and verify your email. Hetzner asks for contact and billing details. Their guide: [Hetzner Account Getting Started](https://docs.hetzner.com/general/billing-and-account-management/account-getting-started/).

## 2. Create a project

In the [Hetzner Cloud console](https://console.hetzner.cloud/), create a new project just for this, for example `snapchain`. A separate project keeps the token's reach small and makes cleanup easy to check: when you are done, the project should be empty. Hetzner explains projects in its [Cloud FAQ](https://docs.hetzner.com/cloud/general/faq/).

## 3. Create an API token

Inside the project, create an API token with Read & Write permission. Hetzner's steps: [Generating an API token](https://docs.hetzner.com/cloud/api/getting-started/generating-api-token/). Hetzner shows the token only once.

Put it in your shell without typing it into the command line, so it stays out of your shell history:

```bash title="your computer"
read -rsp 'Hetzner token: ' HCLOUD_TOKEN && export HCLOUD_TOKEN && echo
```

:::danger[Keep the token secret]
Anyone with this token can create servers on your bill. Do not commit it, paste it into a chat or an AI assistant, or put it in a file inside the repo. The scripts read it from the environment and never print it. If it leaks, delete it in the console and create a new one.
:::

You need to run that `read` line again in every new terminal.

## 4. Install the tools

| Tool | Why | Install |
|---|---|---|
| `hcloud` | Talks to Hetzner | [hetznercloud/cli](https://github.com/hetznercloud/cli) (macOS: `brew install hcloud`) |
| `jq` | Reads JSON in the scripts | `brew install jq` or `sudo apt install jq` |
| `ssh`, `curl` | Reach the server | Already on macOS and most Linux systems |
| Node.js 22.12 or later (22.x, 24.x or 26+), npm | Builds the app | [nodejs.org](https://nodejs.org/) |

```bash title="check"
hcloud version && jq --version && ssh -V && curl --version && node --version && npm --version
hcloud server list        # works once HCLOUD_TOKEN is set; an empty list is fine
```

## 5. Add your SSH key

If you do not have a key yet, make one, then upload the public half to the project:

```bash title="your computer"
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519      # skip if the file exists
hcloud ssh-key create --name my-key \
  --public-key-from-file ~/.ssh/id_ed25519.pub
hcloud ssh-key list
```

`my-key` is the name you pass as `SSH_KEY=my-key` in step 1 of the Quickstart. Keys belong to one project, so upload it to the project you made above. The `hcloud ssh-key create` command is from the [hcloud CLI tutorial](https://github.com/hetznercloud/cli/blob/main/docs/tutorials/create-a-server.md).

## 6. Check your volume limit

New accounts can rent at most 1024 GB of volumes in total. The node needs a bigger disk than the server has, so this limit decides the volume size. You can see your limits at [console.hetzner.cloud/limits](https://console.hetzner.cloud/limits). With the 1024 GB limit, use `VOLUME_GB=1000`, which is what we ran.

## 7. Pick the server

| Setting | What we used | Why |
|---|---|---|
| Server type | `cax31`: ARM64, 8 vCPU, 16 GB RAM, 160 GB disk | The node needs 16 GB of RAM. The x86 type `cx43` was sold out in fsn1, nbg1 and hel1 on 2026-10-18. The Snapchain, statsd and Grafana images all have ARM64 builds. |
| Volume | 1000 GB | Fits the new-account limit. The database reached 557.86 GB. |
| Location | `fsn1` (Falkenstein) | The script's default. Server and volume must be in the same location. |
| Image | Ubuntu 24.04 | The script's default. |

Server types sell out. On 18 Oct 2026 at 18:48 IST, Hetzner listed cax31 and cx43 as sold out in fsn1, nbg1 and hel1. The cheapest type with 16 GB of RAM for sale in fsn1 was cpx42 (x86, 8 vCPU, 16 GB RAM) at $0.1314 an hour, at most $81.99 a month. With the IPv4 address and the 1000 GB volume that comes to about $159 a month. We have not run the node on cpx42.

To check before you rent, run the price check below. If the type is sold out, `provision.sh` says so and lists the types for sale in `LOCATION`, cheapest first. Then set `SERVER_TYPE`, or `LOCATION` (fsn1, nbg1, hel1, ash, hil or sin).

## 8. What it costs

From Hetzner's price list on 2026-10-18, in USD:

| Item | Price |
|---|---|
| cax31 | $0.040 an hour, at most $24.99 a month |
| Public IPv4 | $0.001 an hour, at most $0.60 a month |
| 1000 GB volume | $76.70 a month ($0.0767 per GB). Hetzner bills it by the hour; we estimate about $0.123 an hour (monthly price ÷ 625 hours, the ratio of the server's own monthly and hourly prices) |
| Total | About $0.164 an hour. About $102 a month if you leave it on (each item stops at its monthly price). |

Our sync took 14 h 06 m from renting the server, about $2.31 at these prices. We worked these out from the price list; we have not seen an invoice yet. To see the price before creating anything:

```bash
ESTIMATE_ONLY=1 SERVER_TYPE=cax31 VOLUME_GB=1000 ./provision.sh
```

## 9. Run the 3 steps

Follow the [Quickstart](../quickstart/). First get the code and `cd` into it, as its first block shows (`git clone`, then `cd snapchain-tutorial`). In short:

```bash title="your computer"
MY_IP=$(curl -4 -s https://ifconfig.me)
echo "$MY_IP"        # must print an address; if it is empty, run the line above again
IP=$(SSH_KEY=my-key SERVER_TYPE=cax31 VOLUME_GB=1000 \
  WATCHDOG=0 SSH_SOURCE_CIDRS="$MY_IP/32" \
  ./provision.sh)
ssh root@$IP "SNAPCHAIN_AGREE_NO_REWARDS=yes MIN_FREE_GB=900 bash -s" < node.sh
./deploy-client.sh "$IP"
```

With `WATCHDOG=0` the server keeps running until you delete it. If you only want to try it, provision.sh can delete the server after 24 hours instead; see [If you only want to try it](../quickstart/#if-you-only-want-to-try-it).

:::tip[Find your server's IP again]
In any new terminal, run `IP=$(hcloud server ip snapchain-read-node)`. It needs `HCLOUD_TOKEN` set.
:::

## 10. Delete everything

```bash title="your computer"
CONFIRM=snapchain-read-node ./teardown.sh
```

`teardown.sh` deletes the server, its volume and the firewall, then lists what is left. Afterwards, check these yourself, either in the console or with the CLI:

```bash
hcloud server list
hcloud volume list         # volumes bill even when no server uses them
hcloud firewall list
hcloud primary-ip list     # an unassigned primary IP still bills
hcloud ssh-key list        # teardown keeps your key; delete it if you like:
# hcloud ssh-key delete my-key
```

When all lists are empty (except your SSH key) you pay nothing more. Then delete the API token in the console if you no longer need it. Review the script before running it: <RepoLink path="teardown.sh" />
