## The 3 steps

Run these on your own computer, from the repo folder. [Do it on Hetzner](hetzner/) covers the account, token and SSH key you need first.

```bash title="1. Rent a server"
MY_IP=$(curl -4 -s https://ifconfig.me)
IP=$(SSH_KEY=my-key \
  SERVER_TYPE=cax31 \
  VOLUME_GB=1000 \
  MAX_USD=5 \
  EXPECTED_HOURS=16 \
  SSH_SOURCE_CIDRS="$MY_IP/32" \
  ./provision.sh)
```

```bash title="2. Start the node (about 14 hours)"
ssh root@$IP \
  "SNAPCHAIN_AGREE_NO_REWARDS=yes MIN_FREE_GB=900 bash -s" \
  < node.sh
```

```bash title="3. Open the app"
./deploy-client.sh "$IP"
```

The [Quickstart](quickstart/) has the same commands with what each one prints and how to check it worked. To stop paying, run `CONFIRM=snapchain-read-node ./teardown.sh`.

<div class="numbered">
  <section>
    <p class="label">01 / NODE</p>
    <p class="claim">The node is yours.</p>
    <p><code>node.sh</code> runs the official Snapchain bootstrap. The node loads a snapshot, then fetches each new block from the validators. On a 1000 GB disk it also sets up two small helpers so the disk does not fill up.</p>
  </section>
  <section>
    <p class="label">02 / APP</p>
    <p class="claim">The app talks only to your node.</p>
    <p>Caddy serves the app and the node's <code>/v1</code> API from one HTTPS address. You can read a feed, mute people or words, and, after adding a key, post casts, likes and follows.</p>
  </section>
  <section>
    <p class="label">03 / SIGNER</p>
    <p class="claim">Adding a key costs no gas.</p>
    <p>A new app key is one signed <code>KEY_ADD</code> message. Mainnet has accepted these since engine version V16 on 2026-05-07 (<a href="https://snapchain.farcaster.xyz/guides/writing-messages">writing-messages</a>). A read node passes it on to the validators (<a href="https://snapchain.farcaster.xyz/node-types#message-submission-and-the-mempool">node-types</a>). We have not tried this on mainnet yet.</p>
  </section>
</div>

## What we have and have not tried

We ran a full mainnet sync, the HTTPS app and a read-only browser test (16 of 16 checks passed). We sent one deliberately broken message, and the node rejected it.

Not tried yet:

- A real `KEY_ADD`, cast, like or follow on mainnet.
- `teardown.sh` on real servers.
- `node.sh` installing the disk helpers during a live sync.
