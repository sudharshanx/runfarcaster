## What a read node does

- It downloads a snapshot of the network, then fetches each new block from the validators.
- It keeps a full copy of every Farcaster message, and answers questions about them over HTTP.
- It passes signed messages you send it on to the validators. See [Tutorial step 2](../tutorial/#step-2-your-node-passes-messages-on).
- Validators make the blocks. A read node never does, and it earns no rewards. The official bootstrap asks you to accept that; `SNAPCHAIN_AGREE_NO_REWARDS=yes` gives that answer for you. Read it first at [Getting Started](https://snapchain.farcaster.xyz/getting-started).

## What you need

- A Hetzner Cloud account with an empty project, an API token for it with Read & Write access, and your SSH key uploaded to it. [Do it on Hetzner](../hetzner/) covers each one.
- On your computer: [`hcloud`](https://github.com/hetznercloud/cli), `jq`, `ssh`, `curl`, and Node.js 22.12 or later with npm.
- A Hetzner volume limit of at least 1000 GB. Check it at [console.hetzner.cloud/limits](https://console.hetzner.cloud/limits).
- About 14 hours during which the server can run without you.
- Only to post: a Farcaster account. Use a test account. Reading needs no account.

```bash title="Check the tools"
hcloud version && jq --version && node --version
hcloud ssh-key list          # needs HCLOUD_TOKEN set
```

Set the token without it landing in your shell history:

```bash
read -rsp 'Hetzner token: ' HCLOUD_TOKEN && export HCLOUD_TOKEN && echo
```

The scripts read `HCLOUD_TOKEN` from the environment and never print it. Do the same in each new terminal.

## A Farcaster account, only for posting

Reading the feed needs no account. Posting needs an FID with storage, plus its recovery phrase. Registering an FID and paying for storage are onchain actions; see the [Farcaster docs](https://docs.farcaster.xyz/). A test account needs its own FID and storage. We do not cover creating one.

## Two Hetzner limits we hit

| Limit | What you see | What to do |
|---|---|---|
| New accounts may rent at most 1024 GB of volumes in total, across all projects. The official docs ask for 1.5 to 2 TB. | `volumes size limit exceeded (resource_limit_exceeded)` | Use `VOLUME_GB=1000`, as in the [Quickstart](../quickstart/). `node.sh` then adds two disk helpers so the snapshot fits. |
| The x86 16 GB type `cx43` showed `available: false` in fsn1, nbg1 and hel1 on 2026-10-18. | `provision.sh` refuses the type | Use `SERVER_TYPE=cax31` (ARM64). The Snapchain, statsd and Grafana images all have ARM64 builds. `SERVER_TYPE=` with no value picks the cheapest type for sale. |

## What it costs

| Item | Price (Hetzner list, 2026-10-18, USD) |
|---|---|
| cax31 (ARM64, 8 vCPU, 16 GB RAM, 160 GB disk) | $0.040 an hour |
| Public IPv4 | $0.001 an hour |
| 1000 GB volume | $0.0767 per GB per month, about $0.123 an hour |
| Total | About $0.164 an hour. About $120 a month if you leave it on. |

Our run cost about $2.31 from renting the server to a synced node, 14 h 06 m. We calculated that from the price list; we have not seen the invoice.

```bash title="See the price, create nothing"
ESTIMATE_ONLY=1 SERVER_TYPE=cax31 VOLUME_GB=1000 EXPECTED_HOURS=16 ./provision.sh
```

### How to stop paying

- `CONFIRM=snapchain-read-node ./teardown.sh` deletes the server, the volume and the firewall, then lists what is left. The node's database is on the volume, so it goes too.
- `watchdog.sh` runs on your computer. It calls `teardown.sh` before the bill reaches `MAX_USD`, after 24 hours, or when the node has made no progress for 2 hours. `MAX_USD` is in your Hetzner account's currency. The [Quickstart](../quickstart/#optional-a-spending-cap) has the command.
- `provision.sh` creates nothing if the hourly price × `EXPECTED_HOURS` is above `MAX_USD`. The default `MAX_USD` is 2.

:::caution
We have run `teardown.sh` only with `DRY_RUN=1` and against a fake `hcloud` in tests. After it finishes, look in the Hetzner console yourself.
:::

## Seed phrases and app keys

:::danger[The recovery phrase controls the whole account]
Use a test account. Only type a recovery phrase into code you have read, or code from people you trust, on your own computer. Never paste it into an AI assistant or a chat. If an app you already trust can give you an app key, use that instead.
:::

What our app does if you give it the phrase (<RepoLink path="client/src/signer.ts" />):

1. Your browser makes a new ed25519 app key.
2. The browser uses the phrase once to sign one gasless `KEY_ADD` with your custody address. There is no transaction and no gas.
3. Nothing stores, logs or sends the phrase. Only the signed `KEY_ADD` goes to your node.
4. The app key is saved in this browser's `localStorage`. **Forget app key** deletes it there; the key stays valid on the network until it expires.

JavaScript cannot promise that the browser has wiped the phrase from memory. That is one more reason to use your own computer and a test account.

| The app key can | The app key cannot |
|---|---|
| Post casts (`CAST_ADD`) | Move money or sign transactions |
| Like and recast (`REACTION_ADD`) | Delete casts, unfollow or edit your profile; we do not ask for those scopes |
| Follow (`LINK_ADD`) | Approve or cancel other keys (`KEY_ADD` and `KEY_REMOVE` are never scopes) |
| Work until it expires: 7 days by default, 90 at most, renewed each time it is used | Keep working after your custody address cancels it |
